None provides structured request questions or a separate initiator decision history. A local notebook adds structure without claiming delivery to a trusted person or changing request status.

## Exact domain
Owner/request/reviewer IDs are strict canonical UUID values (case-insensitive identity normalized at boundary). Each record binds owner to context.requesterID and requestID. Context includes requester/reviewer names, category, request description/status/update time, optional recommendation/note/responded time. Trusted reply snapshots come only from this context, preserve attributed name/ID and exact recommendation/note/reported timestamp; users never type or edit another person's reply in this notebook. Duplicate identical reply content is not appended. New source context never rewrites old decision snapshots.

Up to25 personal questions per request, stableUUID, nonblank title<=300characters, optional note<=2000, status open/checked/notApplicable. No automatic completion or inference. Explicit choices wait/decline/clarify/proceed belong to initiator, require confirmation and nonblank reason<=2000; allow open questions but export them explicitly. Decision snapshot independently retains current context and all questions. At most20 decisions and20reply snapshots; repeated identical confirmed decision is a no-op. An edit/newcontext makes latest decision noncurrent until explicitly recorded again. No automatic verdict from trusted recommendation. At least one question required to record a decision. Local dates use device clock and are not trusted timestamps.

## Storage/privacy
Separate per-account private archive, safeUUID filename; schema1 ownerID and up to100 unique request records. Missing file starts empty; present malformed/future/wrong-owner/duplicate IDs/invalid relations reject and block writes without replacing old bytes. File cap10MiB. Atomic same-directory durable replacement, publish only after success; save failure keeps visible draft for retry. No old preferences/session/requests file touched. Archive persists across signout but is inaccessible to other accounts; notebook view is removed/blocked on account change and every open requires current authorized request. Existing account deletion success purges this account's new local file, with visible error if local cleanup fails. Explicit delete-local-notebook confirmation removes only this new record and leaves server request untouched.
